## 항목 3. 핵심 기술 원리 적용 — PASS

| # | 체크 항목 | 판정 | 코드 근거 / 인터뷰에서 기대하는 답변 |
|---|---|---|---|
| 1 | 리스트·딕셔너리 선택 이유(장단점) | ✅ | **리스트**: 등록 순서 유지, 화면 번호와 인덱스가 바로 대응(`prompts[n-1]`), `append`로 추가가 쉬움 / 단점: 제목으로 찾으려면 전체 순회(O(n)), 중간 삭제 시 번호가 밀림. **딕셔너리**: 필드를 이름으로 접근해 가독성이 높고 필드 추가가 쉬움 / 단점: 키 오타가 실행 중 `KeyError`로만 드러남 |
| 2 | while 사용 이유와 종료 조건 | ✅ | 사용자가 종료할 때까지 몇 번 반복할지 모르므로 `while True`. 종료 조건은 `0` 입력 시 `break` **하나로 일원화**. 잘못된 입력은 종료하지 않고 안내 후 계속. 추가로 `Ctrl+C`/`EOF`(`KeyboardInterrupt`, `EOFError`)도 `__main__`에서 잡아 정상 종료 메시지 출력 |
| 3 | "제목 또는 내용 포함" 구현 방식 | ✅ | `keyword in prompt["title"].lower() or keyword in prompt["content"].lower()` — 부분 문자열 `in` 연산 + `or`로 두 필드 중 하나만 맞아도 포함, 검색어와 대상 모두 `lower()`로 대소문자 무시. 조건을 `lambda`로 `find_prompts()`에 넘겨 카테고리 조회·즐겨찾기 목록과 같은 필터 함수를 재사용 |
| 4 | 브랜치 분리 이유와 병합 시점/기준 | ✅ | `feature/prompt-list`에서 목록 기능을 따로 개발 → 기능 완성·동작 확인 후 `--no-ff` 병합(`94f5351`). 이후 카테고리/검색 기능이 목록 출력(`print_prompt_line`)에 의존하므로 **의존되는 기능을 먼저 완성해 병합**한 흐름으로 설명 가능 |

**참고**: 브랜치 분리는 1회(목록 기능)만 있습니다. PASS 기준은 충족하지만, 기능마다 브랜치를 나누는 연습을 더 하면 좋습니다.

## 총평

- **잘한 점**: 요구 기능을 모두 정확히 구현했고, 빈 값·범위·숫자 아닌 입력·빈 목록·`Ctrl+C`까지 예외 상황을 꼼꼼히 처리했습니다. 검색/카테고리/즐겨찾기 결과에 **전체 목록 기준 번호**를 유지해 바로 상세 보기·즐겨찾기에 쓸 수 있게 한 점, 직접 입력 카테고리가 조회 메뉴에 자동 반영되는 점이 사용성 측면에서 돋보입니다. 기본 데이터를 이전 미션의 실제 프롬프트로 채운 것도 좋습니다. README 완성도가 높습니다.
- **보완할 점**: ① Git 사용자 정보와 커밋 작성자를 본인으로 설정, ② 기본 브랜치를 `main`으로 정리하고 기능 브랜치도 push, ③ 실제 터미널 캡처로 증빙, ④ 보너스(JSON 영속화, 수정·삭제, 조회수) 도전 권장.
- **인터뷰 시 유의**: 커밋 대부분이 AI 도구 계정으로 작성되었으므로, 항목 2~4는 학습자가 코드를 보며 **직접** 설명하는지 확인 후 최종 확정하세요.
